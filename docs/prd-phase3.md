# 航启主页 / BUAA-Start 三阶段 PRD

## 术语

| 术语 | 含义 |
| --- | --- |
| 完全功能模式 | 主页默认形态：显示时钟、搜索框与时钟行按钮，功能区显示五张功能卡片与快捷方式。 |
| 仅时钟与背景模式 | 主页只显示时钟与背景图的形态：隐藏搜索框、时钟行按钮与整个功能区，不显示切换按钮，点击视口任意位置退出。 |

两个模式是主页的两端状态；单独关闭“显示功能区”或“显示功能按钮”时得到的中间形态，不属于上述任一模式。

## 1. 三阶段目标

- 把认证从“浏览器手动填写四类凭据”升级为**应用内统一登录**：一次学号 + 密码，由本地中继完成学校统一认证，并派生四类数据源所需凭据。
- 凭据不再存放在浏览器，改由中继**加密保存**在本机；前端请求不再携带凭据。
- 主页增加外观与信息密度控制：五张功能卡片可单独关闭，功能区与时钟行按钮可隐藏，并可在完全功能模式与仅时钟与背景模式之间切换。
- 背景从仓库内置图片扩展为**用户指定的本机目录**，从该目录随机取图。

三阶段完成标准：首次使用只需在设置页登录一次；本机凭据文件中无明文；关闭卡片或隐藏功能区后主页按预期重排或只剩时钟；自定义背景目录可用，异常时可回退内置背景。

## 2. 与一、二阶段的关系

- 一阶段交付：主页基础、快捷入口、本地待办、番茄钟、课表、考试、设置、本地中继。
- 二阶段交付：SPOC、博雅、阳光、番茄钟自动流转与通知。
- 三阶段变更：
	- 一阶段 3.8 与二阶段 4.5 的“四类手动凭据”由统一登录替代；设置页不再提供 Cookie、SPOC Token/RoleCode、博雅 auth_token、阳光 UID/token 输入，相应验收在三阶段不再适用。
	- 一阶段“凭据存 localStorage、随每次请求发送给中继”由“中继加密保存、前端不持有”替代。
	- 二阶段 3.2 中“应用内统一登录”“中继加密存储凭据”两项在三阶段实现，该排除项失效。
	- 一阶段 2.3 非目标继续有效；其中“任何写入操作”指教务业务写操作，不含登录、登出、验证码、会话状态这类认证请求。
	- 一阶段 2.2 剩余的“快捷入口自定义图标/分组”仍未进入三阶段。
- 二阶段的 SPOC、博雅、阳光、番茄钟行为与缓存规则不变，三阶段只改变凭据来源与主页呈现控制。

## 3. 本期范围

### 3.1 本期必须

- 统一登录：设置页新增登录区；一次学号 + 密码登录，必要时输入验证码；自动派生 byxt、SPOC、博雅、阳光四类凭据；显示当前用户与登录状态。
- 中继加密凭据：凭据与派生会话由中继加密保存在本机用户数据目录；前端不保存、不发送凭据；退出登录清除。
- 主页卡片开关：日程、博雅课程广场、待办、专注、阳光五张卡片可单独开关，关闭后隐藏并停止取数；功能区固定 11 行，其余卡片按列上移重排。
- 本机目录背景：设置页指定本机绝对路径，中继扫描第一层图片，随机展示；异常回退内置背景。
- 主页显示开关：可隐藏功能区、隐藏时钟行功能按钮，并可在完全功能模式与仅时钟与背景模式之间切换。

### 3.2 本期不做

- 快捷入口自定义图标/分组、卡片顺序自定义（拖拽换位）。
- WebVPN 与校外加密接入；仅支持直连（校内网络或用户自行连接 VPN）。
- 注册、找回密码、修改密码；登录只在航启内部使用。
- 验证码识别、自动填写或第三方打码。
- 背景轮播、定时切换、模糊度等外观自定义；背景图片不复制进仓库。
- 一阶段 2.3 的全部非目标：多用户/账号体系/权限、移动端适配、SSR/Pinia/React、任何教务业务写操作、研究生 GSMIS、管理后台/成绩管理/教室预约。
- 二阶段 3.2 的其他项：博雅选退课/签到、阳光打卡、SPOC 提交/下载、广场筛选/搜索、番茄钟统计等。

## 4. 功能与验收

### 4.1 统一登录

| 需求 | 验收 |
| --- | --- |
| 设置页新增“统一登录”区，替换原四个手动凭据区；字段为学号、密码、验证码（按需显示）、登录、退出 | 页面只有统一登录区；四个手动凭据输入区不再出现 |
| 登录由中继完成学校统一认证，并自动派生 byxt Cookie、SPOC Token + RoleCode、博雅 auth_token、阳光 UID + token | 登录成功后四类数据源均可取数，无需再填任何凭据 |
| 登录成功后显示姓名、学号与登录时间，并提供退出登录 | 信息与上游返回一致；退出后回到未登录 |
| 登录中禁用重复提交；登录成功后四类数据源自动刷新一次 | 重复点击不产生并发登录；无需手动刷新即可看到数据 |
| 上游要求验证码时展示图片与输入框，并提供刷新验证码 | 出现验证码时可输入完成登录；刷新后图片变化 |
| 登录失败分类提示：账号或密码错误、验证码错误或过期、网络或上游失败、需要重新登录 | 文案可区分，不统一显示“登录失败” |
| 登录成功即整体成功；各数据源独立显示“已派生/派生失败”，失败项可单独重试 | 博雅派生失败不影响 byxt、SPOC、阳光 |
| 凭据由中继保存并注入请求；前端不保存、不发送凭据 | localStorage 与本机请求头中无 Cookie、Token、RoleCode、UID、密码 |
| 会话过期时中继用已保存凭据自动重新登录一次；仍失败则显示“已失效”并保留缓存 | 过期后可自动恢复；失败不显示成“无数据” |
| 主页启动不等待登录校验：认证校验异步进行，缓存优先取数与校验并行 | 慢网或中继不可达时首屏不被校验阻塞；校验期间不误显示“未登录” |
| 退出登录清除中继会话与保存的凭据，需重新输入密码 | 退出后无残留登录态 |
| 仅支持直连；不提供 WebVPN 或连接模式选择 | 页面无模式选择入口 |
| 未登录时主页不新增横幅；各卡片沿用标题状态标签引导到 `/settings` | 主页无新增常驻提示 |

### 4.2 中继加密凭据

| 需求 | 验收 |
| --- | --- |
| 凭据与派生会话由中继保存到系统用户数据目录（Windows 为 `%LOCALAPPDATA%\buaa-start\`） | 该目录存在凭据文件，位置不随项目目录变化 |
| 凭据文件为带完整性校验的对称加密；算法与文件格式见 TRD | 文件内容不含明文学号、密码、Cookie 或任何 token |
| 加密密钥由中继自动生成、独立存放，权限仅当前用户 | 密钥文件不是凭据文件本身；其他用户不可读 |
| 前端 localStorage 不再保存任何凭据；升级后清除旧凭据键 | 升级后需重新登录一次；localStorage 中无凭据字段 |
| 前端请求不再携带凭据请求头；由中继按当前会话注入 | 浏览器请求头中无凭据；中继仍能取数 |
| 中继日志与错误响应不含凭据、密码或 token | 日志仅含方法、路径、状态、耗时 |
| 退出登录删除凭据文件与密钥文件 | 目录内无残留；再次登录重新生成 |
| 缓存不含凭据，仍保存在浏览器 | 清除缓存不影响登录状态 |
| 认证类 POST 仅限登录、登出、验证码、会话状态；业务接口仍为 GET，未列路径仍拒绝 | 构造业务 POST 或未列路径返回错误 |
| 中继仍仅监听 `127.0.0.1` 并校验 Host；凭据不写日志、不发往第三方 | 非本机不可访问；外部请求无凭据 |

### 4.3 主页卡片开关

| 需求 | 验收 |
| --- | --- |
| 设置页新增“主页卡片”区，五个独立开关：日程、博雅课程广场、待办、专注、阳光打卡；默认全部开启 | 五个开关可分别切换并立即生效 |
| 关闭后该卡片不显示，且不再发起该数据源请求；重新开启时按缓存优先刷新 | 关闭期间无该源请求；开启后先显示缓存 |
| 隐藏后同列后续卡片按原相对顺序上移，卡片之间不留空行；功能区始终为 11 行 | 重排后同列卡片无空行，页面不出现错位 |
| 快捷方式仍可放在 11 行中的任意一行；行数与行号不随卡片开关变化 | 编辑态放置区始终为 11 行，已放置的快捷方式停留在原行 |
| 考试区、SPOC 段随所属卡片显示或隐藏，不单独设开关 | 无考试、SPOC 独立开关 |
| 开关状态持久化 | 刷新浏览器后保持 |
| 五张卡片全部关闭时，功能区只显示快捷方式（仍为 11 行） | 页面正常，无报错 |

### 4.4 本机目录背景

| 需求 | 验收 |
| --- | --- |
| 设置页新增“背景”区：绝对路径输入框、保存、清除、重新扫描 | 保存后立即改用该目录；清除后回到内置背景 |
| 中继只扫描所选目录第一层，支持 jpg、jpeg、png、webp、gif、bmp、avif；子目录与其他文件忽略 | 子目录中的图片不出现；非图片文件不出现 |
| 前端通过中继获取图片列表与图片内容；接口只接受该目录内的文件名 | 含 `..` 或路径分隔符的请求被拒绝 |
| 每次打开或刷新应用随机选一张；同一会话内所有页面使用同一张 | 连续刷新出现不同图片；子页面与主页一致 |
| 自定义背景沿用现有暗角遮罩，文字可读性不下降 | 主页与子页面文字仍清晰 |
| 加载自定义背景期间不显示内置背景；加载完成后渐入；加载失败时回退内置背景 | 加载期间不出现内置图切换；成功后渐入；失败后显示内置图 |
| 背景不随页面滚动或触摸板滑动产生位移 | 滚动主页与设置页时背景保持固定 |
| 目录不存在、无图片、无权限或读取失败：回退内置背景并提示，保留已保存路径 | 不出现破图；目录恢复后可重新扫描 |
| 损坏或超过 20 MB 的图片被跳过 | 不阻塞其他图片；全部不可用时回退内置背景 |
| 随机选中的图片读取失败时换下一张，连续失败才回退内置背景 | 单张失败不直接变成内置背景 |
| 用户目录中的图片不复制进仓库、不写入缓存 | 仓库无新增图片；缓存中无图片数据 |

### 4.5 功能区与功能按钮显示开关

| 需求 | 验收 |
| --- | --- |
| 设置页新增“主页显示”区：显示功能区、显示功能按钮两个开关，默认开启 | 两个开关即时生效并持久化 |
| 时钟行右侧新增“仅时钟”切换按钮（眼睛图标），位于设置/编辑/新建按钮左侧 | 按钮可见、可点击 |
| 点击进入仅时钟与背景模式：隐藏搜索框、设置/编辑/新建按钮与整个功能区，只显示时钟与背景 | 页面上仅剩时钟与背景 |
| 该模式不显示切换按钮；点击视口任意位置回到完全功能模式 | 可随时退出；恢复后各卡片与数据按缓存优先加载 |
| 切换模式时背景黑色遮罩交叉淡入淡出（200ms，ease-out） | 遮罩不突变；系统开启“减少动态效果”时不播放 |
| 进入该模式时不发起功能区数据请求；退出后再刷新 | 无多余请求 |
| 模式选择持久化，刷新后仍保持 | 刷新后仍在该模式 |
| 该模式只在 `/` 生效，子页面不受影响 | 子页面显示正常 |
| 关闭“显示功能区”但未进入仅时钟与背景模式：功能区隐藏，搜索框与时钟行按钮保留 | 中间形态与两个模式可区分 |
| 关闭“显示功能区”时同样不发起功能区数据请求；恢复显示后按缓存优先刷新 | 隐藏期间无多余请求 |
| 关闭“显示功能按钮”：设置/新建/编辑隐藏；“仅时钟”按钮仍显示 | 不会失去恢复入口 |
| “仅时钟”按钮不受“显示功能按钮”开关影响 | 独立生效 |

- 设置页移除四个手动凭据区与“清除全部凭据”；“退出登录”承担清除凭据职责，“清除缓存”保持独立。

## 6. 通用规则

- 单用户；数据只存本机，不做云端同步。
- 桌面优先，最小支持宽度约 1024px；不做移动端布局。
- 只读边界：认证类 POST 是唯一写方法例外，业务数据仍只读；不提供任何提交、打卡、选退课、签到入口。
- 凭据只在设置页输入，由中继加密保存；前端仅在登录请求瞬间持有密码，不写入 localStorage。
- 时间按浏览器本地时区显示；教务时间按学校原始时间解释。
- 技术约束不变：Vue 3 Composition API + `<script setup lang="ts">`、TypeScript strict、Vite、Tailwind CSS、Vue Router 4；不引入 Pinia；HTTP 统一封装在 `src/api/client.ts`。
- 本地中继仍是唯一后端；除它之外不引入其他后端，不引入 SSR。

## 7. 边界与失败情况

- 未登录：各数据源显示引导到设置页，不显示成“无数据”；本地待办、番茄钟、快捷入口正常。
- 登录成功但单源派生失败：该源显示“获取失败”与重试，其余源正常。
- 会话过期且自动重登失败：对应数据源显示“已失效”，保留缓存并标注时间。
- 账号或密码错误：提示错误，不清除缓存与已有设置。
- 验证码错误或过期：提示并刷新验证码，可直接重试。
- 上游维护或网络失败：登录失败可重试；已登录状态下按缓存优先降级。
- 登录状态校验失败（中继不可达或上游超时）：卡片按自身请求结果显示缓存或加载失败与重试，不显示成“未登录”；设置页显示校验提示。
- 凭据文件损坏、密钥缺失或无法解密：视为未登录，提示重新登录，不白屏。
- 凭据目录不可写：提示无法保存登录状态，仍可在本次运行内使用会话。
- 背景目录无权限、被删除或为空：回退内置背景并提示，保留路径。
- 背景图片全部不可用：回退内置背景，不出现破图。
- 五张卡片全部关闭：功能区只剩快捷方式，仍为 11 行，编辑与拖拽仍可用。
- 仅时钟与背景模式被持久化后刷新：保持该模式，点击视口任意位置仍可退出。
- 功能区隐藏期间数据不刷新；恢复后按缓存优先补齐。
- 中继未启动：设置页显示连接错误与启动提示，登录不可用，其余本地功能可用。
- localStorage 不可用或损坏：提示并降级为内存状态，不阻塞页面。

## 8. 假设与依赖

- 统一认证流程依据参考 B：预加载获取 execution 与验证码信息、提交学号密码、处理 SSO 票据与 UC 登录状态；具体上游路径、参数与错误判定需补入 `docs/api.md`。
- 派生链路依据参考 B：byxt Cookie 来自 CAS 会话；SPOC 由跳转链取 token 后调用 casLogin 取得 RoleCode；博雅由 SSO 跳转取得 auth_token；阳光由 oauth code 调用 campusAppLogin 取得 uid 与 token。
- 验证码为图片；中继需代理获取并返回给设置页。若参考源码不足以确定浏览器侧流程，需先提供对应 HAR。
- 真实验收需要本地中继、有效学号与密码、校内网络或已连接的 VPN。
- 三阶段实施前需同步更新：`docs/trd-phase3.md`（认证、加密、卡片布局、背景接口、显示状态）、`docs/api.md`（CAS 与派生接口）、`docs/ui-lowfi.md`（统一登录区、背景区、主页显示开关与仅时钟按钮；主页卡片区与卡片重排规则已补入）。
- 一、二阶段的“凭据随请求头发送”机制在三阶段被移除，相关 TRD 章节需改写。

## 9. 三阶段验收清单

- [ ] 统一登录：学号密码登录、验证码、姓名学号显示、退出登录、四类凭据自动派生、单源失败隔离、过期自动重登。
- [ ] 异步校验：主页不等待认证校验；校验期间缓存与卡片正常展示、不误显示“未登录”；校验失败有提示且卡片可重试。
- [ ] 加密凭据：本机目录存在密文凭据；无明文；前端不存不发；日志无凭据；退出后无残留；重启后免登录。
- [ ] 卡片开关：五个开关独立、持久化、隐藏后同列上移重排、固定 11 行、关闭期间停止取数、全部关闭不报错。
- [ ] 本机背景：路径保存与清除、第一层扫描、格式过滤、随机展示、子页面一致、异常回退。
- [ ] 显示开关：功能区与按钮开关独立、完全功能模式与仅时钟与背景模式可双向切换（点击视口任意位置退出、遮罩交叉淡变）、持久化、刷新保持、子页面不受影响。
- [ ] 中继边界：认证类 POST 之外仍只读；Host 校验与 127.0.0.1 监听不变。
- [ ] 类型检查与构建通过；文档同步完成（TRD、API、UI 低保真）。
